# Materials and Methods

## Data retrieval

XevaSet objects for the four cohorts used in this study (UHN breast, UHN lung, McGill breast, and PDXE pan-cancer) were downloaded from Orcestra (https://www.orcestra.ca/xevaset)²⁹. Each data type was extracted from the corresponding XevaSet using the Xeva package²⁷ and stored in CSV format for downstream analysis.

## Case study 1: Transcriptomic modeling of intrinsic PDX growth kinetics

**PDX cohorts and control-arm data.** Breast and lung PDX models and their associated control-arm (untreated) tumor-volume measurements were obtained from XevaDB. For each PDX model, longitudinal tumor-volume measurements from replicate control-arm mice were used to estimate an intrinsic growth rate independent of any treatment effect.

**Estimation of intrinsic tumor doubling time.** For each control-arm mouse, tumor-volume measurements within the first 35 days of the experiment (MAX_DAY = 35) were retained; where multiple measurements existed for the same day, the mean volume was used. Tumor volume was assumed to follow exponential growth, ln(*V_t*) = ln(*V₀*) + *kt*, and the growth-rate coefficient *k* was estimated by ordinary least-squares regression of ln(volume) on time. Doubling time was calculated as ln(2)/*k*. A mouse-level fit was retained only if it had at least 3 time points (MIN_POINTS), a positive growth-rate coefficient (*k* > 0), and a goodness-of-fit R² ≥ 0.8 (MIN_R2). Model-level doubling time was taken as the doubling time of the retained mouse-level fits for that PDX model. The 35-day window was chosen because follow-up duration in this dataset is confounded with growth rate (fast-growing tumors are censored earlier by ethical size limits), so extending the fit window is not a neutral choice; sensitivity analyses varying MIN_POINTS and MIN_R2 independently, and characterizing the follow-up-duration/growth-rate confound, are reported in Supplementary Fig. S1.

**RNA-seq processing.** Bulk RNA-seq expression matrices (TPM/FPKM scale) and per-gene biotype annotation were obtained from XevaDB for each cohort. Expression matrices were restricted to protein-coding genes and to PDX models with matched doubling-time estimates. Genes were retained if expression was ≥1 (TPM/FPKM) in at least max(3, ⌈0.20 × *n*⌉) samples, where *n* is the number of models in that cohort, and then log2(*x* + 1)-transformed. Genes with near-zero variance (variance ≤ 1 × 10⁻⁸) after transformation were removed. This yielded 75 breast and 27 lung PDX models with matched RNA-seq and doubling-time estimates, out of 96 and 36 total evaluable control-arm models, respectively.

**Definition of fast- and slow-growing classes.** Doubling time was log1p-transformed prior to all downstream modeling. Within each outer cross-validation training fold (see below), the 33rd and 67th percentiles of log1p(doubling time) were computed from the training fold only and used to define fast-growing (≤33rd percentile) and slow-growing (≥67th percentile) extreme groups; both the training and held-out test fold were then restricted to samples falling into these training-derived extreme groups, and this training-only cutoff was used to binarize both the training and test labels (slow growth = 1, fast growth = 0). Models in the middle third were excluded from that fold's classification task. Because cutoffs were re-derived independently in every fold from training data only, no information from a held-out test fold was used to define its own class labels.

**Feature selection.** Within each training fold, highly variable genes (HVGs) were selected as the *N* genes with the highest variance in that fold's training-extreme expression matrix (computed on the training fold only, never on held-out test data). *N* was fixed per cohort — 100 for breast and 600 for lung — and shared identically across all three classifiers described below; it was not tuned as part of any model's hyperparameter search. This choice was empirically justified by comparing classifier performance across a grid of candidate values, holding all other hyperparameters fixed (Supplementary Fig. S2).

**Cross-validation design.** Model performance was assessed using repeated k-fold cross-validation (RepeatedKFold, scikit-learn), with 5 splits × 10 repeats for breast (50 outer folds) and 3 splits × 10 repeats for lung (30 outer folds; random_state = 42). An outer fold was excluded from all downstream analysis if any of the following held, evaluated in order: (i) fewer than 4 training-extreme samples; (ii) only one class present among training-extreme samples; (iii) only one class present among test-extreme samples; or (iv) too few training-extreme samples per class to construct a valid inner cross-validation split (see below). For lung, 2 of 30 outer folds were excluded (both for reason iii), leaving 28 completed folds; all 50 breast outer folds were completed.

For hyperparameter selection within each completed outer fold, an inner stratified k-fold split (StratifiedKFold) was constructed from that fold's training-extreme samples only, with the number of inner splits set to min(4, minimum per-class training count) and shuffled (random_state = 42); folds with fewer than 2 possible inner splits were excluded (criterion iv above).

Three classifiers were trained independently within each completed outer fold, all using the same fold-specific HVG set and the same outer training/test split.

*Elastic net.* Features were standardized (zero mean, unit variance) using a scaler fit on the training fold only. A logistic regression classifier with elastic-net penalty was fit using LogisticRegressionCV (solver = "saga", scoring = "roc_auc", max_iter = 20,000), with C and l1_ratio jointly selected via the inner cross-validation splits from a grid of l1_ratio ∈ {0.1, 0.5, 0.9} and C ∈ {0.01, 0.1, 1, 10}.

*Random forest.* A random forest classifier (RandomForestClassifier; 500 trees, max_features = "sqrt") was fit with max_depth and min_samples_leaf selected via a nested grid search over max_depth ∈ {3, 6} × min_samples_leaf ∈ {1, 2}, choosing the combination with the highest mean AUROC across the inner cross-validation splits (fit and scored using only the outer fold's training-extreme data).

*Lassoed forest.* A random forest (same architecture and hyperparameter grid as above) was first fit on the training-extreme data; its own max_depth/min_samples_leaf were selected independently via the same nested inner-CV procedure, but scored on the post-lasso AUROC of the pipeline described below (using a fixed regularization strength, C = 1, for both the ridge and lasso steps during this hyperparameter search, to avoid a third level of nested cross-validation on already-small fold sizes). Each of the forest's 500 trees' predicted positive-class probability was used as a feature, producing a per-sample "tree design matrix." After standardizing this matrix, an initial ridge-penalized logistic regression (LogisticRegressionCV, penalty = "l2", solver = "lbfgs", scoring = "roc_auc") was fit with C selected via inner cross-validation from C ∈ {0.001, 0.01, 0.1, 1, 10, 100}. Adaptive-lasso weights were computed as 1/(|β_ridge| + ε)^γ (ε = 10⁻³, γ = 1), and a weighted L1-penalized logistic regression (LogisticRegressionCV, penalty = "l1", solver = "saga", scoring = "roc_auc") was fit on the reweighted tree-probability matrix, again with C selected via the same inner cross-validation and grid, yielding a sparse, adaptive-lasso-selected subset of trees for the final probability prediction.

**Model evaluation.** For each completed outer fold and each classifier, predicted probabilities for the held-out test-extreme samples were evaluated against the binary fast/slow labels using the area under the receiver-operating-characteristic curve (AUROC), and against the continuous log1p(doubling time) of the same test-extreme samples using Spearman and Pearson correlation. Per-classifier performance is reported as the mean ± population standard deviation (ddof = 0) across all completed outer folds for each cohort.

**Feature importance.** Random forest feature importance was quantified two ways: (i) mean Gini importance, averaged across all folds in which a gene was included in the fold-specific HVG set, and (ii) TreeSHAP values (shap.TreeExplainer, interventional feature perturbation, model_output = "probability"), computed for the slow-growth class on each fold's held-out test-extreme samples using that fold's training-extreme data as background. For each gene, a selection frequency was defined as the fraction of completed outer folds in which the gene was included in that fold's HVG set (and therefore available to the random forest), and a mean |SHAP| value was defined as the sum of absolute SHAP attributions across all held-out test predictions divided by the total number of held-out test predictions (genes not selected in a given fold contribute zero to this sum for that fold's predictions). Elastic net feature importance was summarized as the standardized coefficient (on the scale used for model fitting) averaged across all completed folds, with genes absent from a fold's HVG set contributing a coefficient of zero to that fold; a nonzero frequency was defined analogously to the random forest's selection frequency, as the fraction of completed folds with a nonzero coefficient. For all gene-ranking and gene-overlap analyses, genes were required to have a selection/nonzero frequency ≥ 0.50 across completed folds before being ranked or displayed.

**Cross-model and cross-cohort comparison.** Within each cohort, the top 20 genes ranked by mean Gini importance (random forest) and by absolute mean standardized coefficient (elastic net) were intersected to assess within-cohort agreement between classifiers. Concordance between elastic net coefficients and random forest SHAP importance was further assessed by Pearson correlation between absolute standardized coefficient and mean |SHAP| value, computed separately for genes associated with each growth direction. Between cohorts, the top 100 genes per cohort (after the 0.50 frequency filter, ranked by mean |SHAP|) were intersected to identify shared predictive genes; for each shared gene, direction of association (fast- vs. slow-growth) in each cohort was determined from the sign of the mean signed SHAP value across all held-out test predictions in that cohort, and concordance was defined as agreement in sign between cohorts.

**Gene-set enrichment analysis.** GSEA was performed independently of the classifiers above, using the full (non-HVG-restricted) protein-coding expression matrix for each cohort. Fast- and slow-growth groups were defined globally (not per fold) using the 33rd and 67th percentiles of log1p(doubling time) across all RNA-matched models in that cohort. For every gene, a ranking statistic was computed as the Welch's *t*-statistic (unequal variance) for slow-growth versus fast-growth mean expression. Genes were ranked by this statistic and analyzed using pre-ranked GSEA (gseapy.prerank; 5,000 permutations, minimum gene-set size 15, maximum gene-set size 500, random_state = 42) against three MSigDB gene-set collections: GO Biological Process (2023), KEGG (2021 Human), and MSigDB Hallmark (2020). Cross-cohort concordance was assessed by matching gene sets tested in both cohorts within each collection; a gene set was considered concordantly enriched if it showed the same sign of normalized enrichment score (NES) and FDR *q* < 0.05 in both breast and lung.

**Statistics and reproducibility.** All analyses were performed in Python 3.13 using pandas (v3.0.2), NumPy (v2.4.4), SciPy (v1.17.1), scikit-learn (v1.8.0), shap (v0.51.0), gseapy (v1.1.13), matplotlib (v3.10.8), seaborn (v0.13.2), and matplotlib-venn (v1.1.2). A fixed random seed (random_state = 42) was used for all cross-validation splitting, model fitting, and GSEA permutation testing to ensure reproducibility. No blinding was applicable, as this is a fully computational analysis of pre-existing PDX growth and expression data.

## Case study 2: Image-based deep-learning classification of drug-response trajectories

**PDX dataset and case selection.** Tumor-volume response data were obtained from XevaDB (the PDXE pan-cancer dataset⁶). Model-drug batches were eligible for inclusion if the batch had a defined control arm (a non-missing control field in the Xeva experimental design) and the corresponding treatment model had a non-missing mRECIST classification (CR, PR, SD, or PD). Because complete and partial responses are comparatively rare in PDXE, all eligible CR and PR curves were retained; the remaining sampling budget was allocated first to stable disease (SD, up to half of the remaining slots) and then progressive disease (PD, the remainder), sampled at random with a fixed seed (seed = 1), to assemble a stratified set of 1,300 model-drug pairs. The realized mRECIST composition of the selected set was 124 CR (9.5%), 300 PR (23.1%), 438 SD (33.7%), and 438 PD (33.7%).

**Tumor-volume plot generation.** For each selected batch, a tumor-volume plot was generated with Xeva's *plotPDX* function, displaying volume-normalized control- and treatment-arm growth curves (control: #a6611a; treatment: #018571) over a fixed 50-day window, with a horizontal reference line marking complete tumor regression. Plots were rendered at 6.2 × 6 in, 120 dpi, saved as PNG, and compressed to WebP. Per-batch engineered response statistics (mRECIST call, best response and time-to-best-response, AUC, growth slope at the model level; slope, angle, AUC, and area-between-curves at the batch level; tumor growth inhibition, TGI) were exported from XevaSet alongside each image as a manifest for downstream feature-based modeling.

**Ground-truth response labeling.** All 1,300 curve images were independently reviewed by three raters with oncology expertise, blinded to model-drug identity and to each other's ratings, and classified into five ordinal response categories (Highly Resistant, Resistant, Intermediate, Sensitive, Highly Sensitive). Consensus labels were assigned by majority vote (≥2 of 3 raters in agreement); curves with three-way rater disagreement (*n* = 33, 2.5%) were excluded, leaving 1,267 consensus-labeled curves for modeling. Individual-rater agreement with the consensus label was 86.2%, 77.2%, and 84.5% for the three raters, respectively. Consensus category frequencies were 305 (Highly Resistant), 359 (Resistant), 299 (Intermediate), 213 (Sensitive), and 91 (Highly Sensitive) (Fig. 3b).

**Image preprocessing for deep learning.** To prevent the model from learning from textual metadata rather than curve shape, the top 100 pixels of each raw plot (containing the batch title) were cropped, yielding uniform 744 × 620-pixel images with no textual annotation. All subsequent image-based modeling used these cropped images exclusively.

**Cross-validation design.** All models were evaluated using stratified 5-fold cross-validation on the 1,267 consensus-labeled curves (StratifiedKFold, scikit-learn v1.8.0; shuffle = True, random_state = 42), stratified on the five-category consensus label. The fold assignment was generated once and used identically by both the image-based and feature-based models, so that both were evaluated on exactly the same held-out partitions. For each of the 5 outer folds, the held-out fold (~253–254 curves) served as the test partition and was scored exactly once; the remaining four folds (the training pool, ~1,013–1,014 curves) were used for model fitting and internal model selection, as described separately for each model below.

**Image-based model (ResNet18).** A ResNet18 convolutional neural network (torchvision v0.26.0, ImageNet-pretrained weights) was used, with the final fully connected layer replaced by a linear classifier mapping 512 features to 5 output classes. Images were resized to 224 × 224 pixels and normalized using standard ImageNet channel statistics. Within each outer fold's training pool, a further stratified 85/15 split (random_state = 42) separated a training set from a validation set used only for learning-rate scheduling, early stopping, and checkpoint selection; the outer test fold was never used for these purposes. Training images were augmented with random-resized cropping (scale 0.8–1.0) and brightness/contrast jitter. Class imbalance was addressed with a class-weighted random sampler (inverse class frequency) applied to the training set and matching class weights in the cross-entropy loss. Models were optimized with Adam (weight decay = 1 × 10⁻⁴) using layer-group-specific learning rates (1 × 10⁻⁶ for layer1/layer2, 1 × 10⁻⁵ for layer3/layer4, 1 × 10⁻⁴ for the final classifier), with learning rate reduced on validation-loss plateau (factor = 0.1, patience = 3 epochs). Training used a batch size of 32 for up to 50 epochs with early stopping (patience = 7 epochs without validation balanced-accuracy improvement); the checkpoint with the best validation balanced accuracy was reloaded and used for the single evaluation on that fold's held-out test partition. Training was performed using PyTorch (v2.11.0). All relevant random seeds (Python, NumPy, PyTorch CPU/GPU, and the data sampler) were fixed, and cuDNN determinism flags were enabled where applicable; end-to-end reproducibility of fold-level results was empirically confirmed across independent reruns.

**Feature-based model (random forest).** Fourteen engineered features exported from Xeva (model-level: mRECIST call [encoded CR/PR/SD/PD as 0–3], best response, time to best response, average best response and its timing, AUC, growth slope; batch-level: control- and treatment-arm slope, divergence angle, control- and treatment-arm AUC, area between curves, and TGI) were used to train a random forest classifier (scikit-learn v1.8.0, class_weight = "balanced"). A small number of curves (*n* = 2) had non-finite TGI values due to near-zero denominators; these were clipped to the finite maximum/minimum observed within each fold's training partition only, so that no information from the held-out test fold influenced preprocessing. Hyperparameters (number of trees ∈ {100, 200, 300}; maximum depth ∈ {None, 10, 20}; minimum samples per split ∈ {2, 5, 10}; maximum features ∈ {√, log₂}) were selected independently for each outer fold via grid search with an inner 5-fold cross-validation on that fold's training pool, scored by macro-averaged F1. For model-interpretation analyses only (feature importance and SHAP; not used for any reported performance metric), a final random forest was fit using the same grid-search procedure on all 1,267 consensus-labeled curves.

**Performance evaluation.** For each model and outer fold, macro-averaged precision, recall, and F1-score, and balanced accuracy (mean per-class recall) were computed on that fold's held-out test partition. Summary performance is reported as the mean ± SD across the 5 outer folds. A pooled out-of-fold confusion matrix was constructed by concatenating each fold's test-set predictions, such that every one of the 1,267 curves contributed exactly one prediction, made by the model that had not seen it during training.

**Model interpretability.** For the random forest, feature attributions were computed with TreeSHAP (shap.TreeExplainer; SHAP v0.51.0) on the final all-data model; mean absolute SHAP values were computed per feature and per response category. For ResNet18, gradient-weighted class activation mapping (Grad-CAM)⁷ was computed on the final convolutional block (layer4) via forward/backward hooks. For each response category, one correctly classified, genuinely held-out example was selected from the out-of-fold predictions and visualized using the checkpoint from the fold that had held it out during training, so that each explanation corresponds to a true generalization prediction rather than a training example.

**Statistics and reproducibility.** All tabular analyses were performed in Python 3.13 using scikit-learn (v1.8.0), pandas, NumPy, and SciPy; the deep-learning model was trained using PyTorch (v2.11.0) and torchvision (v0.26.0) in a separate environment. Fixed random seeds (seed = 42, unless otherwise noted) were used throughout for cross-validation splitting and model training to ensure reproducibility. Ground-truth rating of response curves was performed blind to model-drug identity and to the other raters' assessments (see above); no other blinding was applicable, as the remaining analyses are fully computational.

## Case study 3: Cross-platform validation of NeST-VNN

**PDX cohorts and data extraction.** Breast cancer PDX models and associated drug-response, experimental-design, and molecular-profile data were obtained from XevaDB for two independent cohorts: a McGill cohort treated with cisplatin and a University Health Network (UHN) cohort treated with carboplatin. For each cohort, the corresponding XevaSet object (Xeva v1.22.1, R v4.4.2) was queried to extract the model table, drug table, per-mouse longitudinal tumor-volume measurements (experiment), treatment/control-arm membership (expDesign), batch-level and mouse-level drug-sensitivity tables (*batch_sensitivity.csv*, *model_sensitivity.csv*), and molecular profiles (mutation and copy-number matrices with gene annotation). For McGill, an additional model-to-omics (biobase) sample mapping (*modToBiobaseMap*) was extracted, as UHN's model identifiers correspond directly to its molecular-profile matrix column names.

**Cohort construction (McGill).** Batches were parsed from the *batch.name* field (format "\<model_id\>.\<drug\>") and restricted to the 32 unique cisplatin-treated models (13 carboplatin-treated batches were also present but not used, owing to insufficient sample size for robust model testing). Each model's omics sample was identified by parsing *modToBiobaseMap.csv*'s *model.id* field (format "\<patient\>.\<passage\>.\<GCRC-number\>\<drug-code\>"; drug code "Ci" denotes cisplatin), collapsing to one row per (model, biobase sample) across molecular data types, and retaining only samples with an available CNV call. One model (GCRC1784) mapped to more than one CNV-bearing biobase sample with no basis for disambiguation and was excluded; two further models (GCRC1986, GCRC2097) had no CNV-bearing omics sample. This yielded 29 cisplatin models with matched sensitivity and omics data.

**Cohort construction (UHN).** Batches containing "CARBOPLATIN" in *batch.name* were retained, excluding resistant-derivative lines (batch names containing "-" or "RES", denoting re-challenge/continuation experiments), yielding 84 non-resistant carboplatin batches. Model identifiers were parsed from *batch.name* and, for purely numeric identifiers, prefixed with "S" to match the corresponding molecular-profile matrix column (e.g., "108099" → "S108099"). Restricting to models with an available CNV column yielded 68 carboplatin models.

**Batch-level response aggregation.** For both cohorts, drug-response outcomes are recorded per individual treatment-arm mouse in *model_sensitivity.csv* (mRECIST, best response, response slope) but analyzed at the batch level. Because a batch can include more than one treatment-arm mouse, a batch-level mRECIST call was derived by majority vote across that batch's treatment-arm mice, with ties broken toward the more resistant call (PD > SD > PR > CR); this aggregation was required for 14/135 McGill batches (across all drugs in that cohort) and for a comparable proportion of UHN batches. The number of treatment-arm mice per batch (n_replicates) was recorded from *expDesign.csv* (count of *arm* == "treatment" rows per *batch.name*) using an identical definition in both cohorts. One UHN model (REF063) had CNV/mutation data but no recorded mRECIST (its single treatment-arm mouse's own mRECIST value was missing); this model was retained in the cohort but excluded from mRECIST-based summaries.

**Replicate-based cohort stratification (UHN).** n_replicates ranged from 1–7 across the 68 UHN carboplatin models (32 models with exactly one treatment-arm mouse), whereas all 29 McGill cisplatin models had exactly one. We therefore defined a "complete" UHN cohort (all 68 models) and a "strict" UHN cohort restricted to models with n_replicates ≥ 2 (36 models), to evaluate whether replicate-supported response estimates altered downstream model-validation results.

**Genomic feature processing.** Mutation and copy-number matrices were restricted to each cohort's models and to the 718-gene panel used by NeST-VNN. Mutation calls were binarized as 1 if any of a whitelist of functional variant classifications was present at that gene (missense, nonsense, frameshift insertion/deletion, in-frame insertion/deletion, splice site, translation start site, nonstop mutation; multiple classifications per cell were split on commas and evaluated jointly) and 0 otherwise, including for genes with no recorded call in a cohort's raw matrix.

Copy-number calls were binarized differently for each cohort, reflecting how each cohort's copy-number values were encoded. McGill's CNV matrix was already GISTIC-style discrete (values in {−2, −1, 0, 1, 2}); amplification and deletion were defined as CN == 2 and CN == −2, respectively. UHN's CNV matrix instead reported near-continuous absolute copy number, and each model's modal copy number across its full (not gene-panel-restricted) profile showed that most UHN models are not diploid at baseline (42/68 had a modal copy number of 3, consistent with whole-genome-duplicated/aneuploid tumor biology; the remainder ranged from 0–7). Amplification was therefore defined relative to each model's own baseline ploidy (CN ≥ 2× that model's modal copy number, floored at a minimum threshold of 4 for the few models whose own modal copy number was 0 or 1) rather than a single fixed cutoff across all models. Deletion was defined as a flat, ploidy-independent CN == 0 in both cohorts, as homozygous loss is unambiguous regardless of ploidy.

**NeST-VNN input preparation and inference.** For each cohort (McGill cisplatin, *n* = 29; UHN carboplatin complete, *n* = 68; UHN carboplatin strict, *n* = 36), binarized mutation, amplification, and deletion matrices were reoriented to model × gene format matching NeST-VNN's expected input files, and a placeholder response file was constructed (label = 0, since no ground-truth response on NeST-VNN's own training scale exists for external PDX inference). A single gene index file was shared across all three cohorts to guarantee identical gene ordering. NeST-VNN's publicly released 5-fold pretrained cisplatin ensemble, trained on cell-line drug-response data from the Cancer Cell Line Encyclopedia (CCLE, release 22Q1)³², was applied to each cohort's prepared input via the model's own inference script (PyTorch v1.13.1, Python 3.9.6; CPU inference, batch size 2,000), producing one continuous predicted-response score per model per fold. All downstream analyses used the mean of the five per-fold predictions as each model's predicted response.

**Definition of a cross-cohort-comparable response endpoint.** mRECIST category proportions differed substantially between cohorts (McGill: 20.7–31.0% in each of CR/PR/SD/PD; UHN: 50.7% PD, 34.3% SD, 9.0% PR, 6.0% CR), making mRECIST unsuitable as a directly comparable cross-cohort ground truth. We instead used the batch-level growth-curve slope angle (an arctan-transformed regression slope of log-tumor-volume on time, in degrees, bounded ±90° by construction), available for both cohorts on an identical, ploidy/drug-potency-independent scale. Control-arm slope distributions were broadly similar between cohorts (median 86.7° McGill vs. 83.7° UHN; two-sided Kolmogorov–Smirnov *D* = 0.357, *p* = 8.2 × 10⁻³), supporting comparable untreated growth behavior and the use of this metric as a cross-cohort baseline; treatment-arm slope distributions differed significantly (*D* = 0.414, *p* = 1.2 × 10⁻³), reflecting differential drug response rather than a measurement-scale artifact. Response was defined using a fixed, cohort-independent threshold on treatment-arm slope: net tumor regression (slope < 0°) as responding, net growth (slope ≥ 0°) as non-responding.

**Cohort comparability analyses.** We assessed whether the two cohorts' molecular input features were broadly comparable prior to modeling by computing (i) the fraction of the 718 NeST-VNN panel genes with any recorded data in each cohort's raw mutation and CNV matrices, (ii) the per-model number of nonzero mutation/CNA/CND events (two-sided Mann–Whitney *U* test, McGill vs. UHN complete), and (iii) a 2-component principal component analysis (scikit-learn v1.6.1) of each binarized feature matrix, fit jointly across both cohorts. CNV coverage was comparable between cohorts (UHN: 711/718 genes, 99.0%; McGill: 717/718, 99.9%), as was per-model CNA/CND event burden (CNA: *U* = 858.5, *p* = 0.317; CND: *U* = 1175.5, *p* = 0.136; both not significant). Mutation coverage differed substantially (UHN: 670/718, 93.3%; McGill: 235/718, 32.7%): UHN mutation and CNV calls were generated by whole-exome sequencing (WES) and McGill's by whole-genome sequencing (WGS); WES's higher per-target sequencing depth likely yields more sensitive mutation calling within this gene panel than WGS's broader but shallower coverage. Per-model mutation event burden was significantly higher in UHN than McGill using the full 718-gene panel (*U* = 1824.5, *p* = 3.8 × 10⁻¹¹); restricting the comparison to only the 232 genes with recorded mutation data in both cohorts substantially weakened, but did not eliminate, this difference (*U* = 1348.0, *p* = 4.2 × 10⁻³), indicating that unequal gene coverage inflates but does not fully account for the observed difference in mutation burden.

**Model validation.** For each cohort, NeST-VNN's average predicted response was evaluated against the fixed-threshold slope-angle response label using the area under the receiver operating characteristic curve (AUROC; scikit-learn v1.6.1), together with a 95% percentile bootstrap confidence interval (2,000 resamples of models with replacement within each cohort, discarding any resample containing only one class; NumPy v1.26.4 Generator, seed = 0). Association between NeST-VNN's continuous predicted response and the continuous slope-angle value was additionally assessed with Spearman rank correlation (SciPy v1.13.1).

**Threshold-sensitivity (robustness) analysis.** Because the fixed-threshold definition of response is one of several reasonable choices, we repeated the AUROC analysis using (i) each cohort's own median treatment-arm slope value as the response cutoff, and (ii) a systematic sweep of cutoffs at every 10th percentile of each cohort's own slope distribution from the 10th to 90th percentile, in each case with the same bootstrap procedure as above. No correction for multiple comparisons was applied across the more than 30 threshold-and-cohort combinations evaluated across this analysis and the primary fixed-cutoff analysis above (fixed 0° cutoff, per-cohort median split, and the percentile sweep, each evaluated in three cohorts); given this number of comparisons, the UHN-strict result reported above should be read as suggestive rather than a robust, standalone finding.

**Statistics and reproducibility.** All Python analyses were performed using Python 3.9.6, pandas (v2.2.3), NumPy (v1.26.4), SciPy (v1.13.1), scikit-learn (v1.6.1), and matplotlib (v3.7.3); NeST-VNN inference used a separate Python 3.9.6 environment with PyTorch (v1.13.1). PDX data extraction from XevaSet objects used R (v4.4.2) and Xeva (v1.22.1). A fixed random seed (seed = 0) was used for all bootstrap resampling. No blinding was applicable, as this is a fully computational analysis of pre-existing PDX drug-response and molecular-profile data.

## Case study 4: Multi-omics prediction of paclitaxel response

**PDX cohort and paclitaxel response phenotyping.** PDX drug-sensitivity records were drawn from the extracted UHN breast cancer XevaSet, comprising batch-level (*batch_sensitivity.csv*), model-level (*model_sensitivity.csv*), and experimental-design (*expDesign.csv*) tables. Batches were filtered to single-agent paclitaxel treatment arms, excluding resistant-derivative sublines. Batch-level mRECIST categories were derived from the per-mouse mRECIST calls recorded in *model_sensitivity.csv* by majority vote across each batch's treatment-arm mice, with ties broken toward the worse response (PD > SD > PR > CR); this mirrors the aggregation method used for the carboplatin case study on the same PDX resource. The primary response label used for all downstream modeling was a binary median split of the batch-level growth-curve angle metric: the median was computed once across the full 80-batch cohort and applied as a fixed threshold to every sample subset used downstream (Sensitive: angle ≥ threshold; Resistant: angle < threshold), rather than being recomputed independently within each differently sized omics subset.

**Multi-omics data processing.** *RNA-seq.* Raw expression values were log2(*x* + 1)-transformed, and genes with zero variance across all profiled samples or within the paclitaxel-treated subset were removed, yielding a matrix of 67 models × 49,348 genes.

*Copy number (CNV).* Absolute gene-level copy number was converted to a ploidy-relative continuous log2 ratio. For each sample, a baseline copy number was defined as the modal copy-number value across the full, unfiltered genome (i.e., computed before any gene-level filtering), floored at 1 to avoid division artifacts in samples with degenerate low baselines. Genes with missingness ≥ 20% across samples were removed, then each remaining value was transformed as log2((CN + 0.5) / baseline); remaining missing values were set to 0 (the neutral, at-baseline value on this scale). This yielded a matrix of 62 models × 10,313 genes. This approach mirrors the ploidy-relative baseline procedure used for CNV in the carboplatin case study on the same PDX resource, extended here to a continuous ratio rather than a binary amplification/deletion call to preserve graded copy-number information.

*Mutation.* Variant calls were binarized per gene per sample using an inclusive functional-variant whitelist (Missense_Mutation, Nonsense_Mutation, Frame_Shift_Del, Frame_Shift_Ins, In_Frame_Del, In_Frame_Ins, Splice_Site, Translation_Start_Site, Nonstop_Mutation), consistent with the mutation-handling convention used for the carboplatin case study. This yielded a matrix of 62 models × 13,029 genes, covering an identical model set to the CNV data. The three-omics overlap (RNA ∩ CNV ∩ Mutation) comprised 62 models.

**Fold-safe feature selection.** To avoid information leakage, feature selection was performed independently within each cross-validation training fold and applied unchanged to the corresponding held-out test fold. RNA features were selected by a variance prefilter (top 2,200 genes), a pairwise-correlation filter (Pearson |*r*| > 0.85, retaining the earlier-ranked gene of each correlated pair), and a final variance filter (top 2,000 genes). CNV features were selected by a positive-variance filter followed by a correlation filter (|*r*| > 0.95). Mutation features were selected by a prevalence filter (present in ≥10 and ≤90% of training samples). For all three omics layers, any gene from a curated 69-gene paclitaxel-prior list present in the training data was force-retained in addition to the filter-selected genes.

**Model training and evaluation.** Four classifier families were evaluated: L1- and L2-penalized logistic regression (liblinear solver, class-balanced weighting), an RBF-kernel support vector machine (probability estimates enabled, class-balanced weighting), and a random forest (500 trees, sqrt max features, class-balanced weighting). Hyperparameters (regularization strength for logistic regression; C and gamma for SVM; max depth and minimum leaf size for random forest) were tuned by grid search with 3-fold stratified inner cross-validation, optimizing AUROC. Outer performance was assessed by 5-fold stratified cross-validation repeated 5 times (25 total folds; random_state = 42 throughout).

Three modeling architectures were compared: (1) single-omics classification, with RNA evaluated both on the full 67-model RNA-profiled cohort and on the 62-model cohort paired across all three omics for direct comparability; (2) early fusion, concatenating each fold's selected RNA, CNV, and mutation features before classification on the 62-model paired cohort; and (3) late fusion/stacking, in which a base classifier was trained per omics layer via out-of-fold predictions on the training fold (inner 3-fold cross-validation) and combined by an L2-penalized logistic-regression meta-model, with a sensitivity analysis comparing logistic regression, random forest, and SVM-RBF as the base-model family.

**Statistical analysis.** For each model/omics/analysis combination, we report the mean AUROC across the 25 repeated cross-validation folds, a 95% confidence interval based on the *t*-distribution, and a one-sample *t*-test against chance performance (AUROC = 0.5). Because repeated cross-validation folds resample the same underlying cohort and are not fully statistically independent, this test is the standard (if somewhat anti-conservative) approach used across most repeated-CV machine-learning reporting, rather than a variance-corrected alternative such as a Nadeau–Bengio test; *p*-values should be interpreted alongside the reported confidence intervals. Benjamini–Hochberg false discovery rate correction was applied across all 23 model/omics/analysis combinations tested.

**Feature importance and pathway enrichment analysis.** To identify RNA features driving classification, we fit a single random forest (identical hyperparameters to the tuned single-omics model) on the full 67-model RNA cohort after applying the same fold-safe-style feature selection to the entire dataset; this model was used only to rank impurity-based feature importances and was not used for any performance estimate. For pathway-level analysis, all 49,348 profiled genes (not the pre-filtered classification feature subset) were ranked by a Welch's *t*-statistic contrasting Sensitive and Resistant models, and tested by pre-ranked gene set enrichment analysis (GSEA; gseapy v1.1.11) against the MSigDB Hallmark (2020), KEGG (2021 Human), and GO Biological Process (2023) gene set libraries (Enrichr collections), using 5,000 permutations, a minimum/maximum gene-set size of 15/500, and a fixed random seed (42). Gene sets were considered significant at a within-collection Benjamini–Hochberg FDR < 0.05.

**Statistics and reproducibility.** All analyses were performed in Python 3.9.6 using pandas (v2.2.3), NumPy (v1.26.4), SciPy (v1.13.1), scikit-learn (v1.6.1), and gseapy (v1.1.11). A fixed random seed (random_state = 42) was used for all cross-validation splitting, model fitting, and GSEA permutation testing throughout; both the classification pipeline and the GSEA permutation test were confirmed to be exactly reproducible across independent reruns of the full analysis. No blinding was applicable, as this is a fully computational analysis of pre-existing PDX drug-response and molecular-profile data.
